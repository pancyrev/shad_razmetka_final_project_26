# Подбор промптов Qwen и Gemma

Этот отчёт относится к прежнему протоколу: VLM возвращала полный объект с ID.
После подбора рабочие промпты адаптированы к ответу только с `boxes`; ID и `error`
добавляются парсером. [Проверка нового протокола](../boxes_only_2026-11-16/README.md).
Текущие `*_tuned` отличаются форматом ответа от испытанных здесь промптов.

По 10 вариантов для каждой модели, включая повтор исходного промпта. Варианты
готовят отдельные агенты; фактически испытанные тексты записаны в `<model>/prompts.json`.
Каталог сохраняет первоначальную дату подготовки; CUDA-прогоны выполняются 16 ноября 2026.

## Протокол

- Все 100 изображений `validation` из `xartik/inaturalist_butterflies`, 61 эталонная
  рамка. Порядок ID и эталонные координаты проверяются по исходному прогону и
  локальной эталонной разметке. Независимый `test` не используется.
- Ревизия датасета: `1316e3c7147d4399a03f90684e191aae4d798f09`.
  SHA256 локального HF Parquet:
  `1bd37f7bd7747801e7896f6605ff977b3328d6571560367b176e802ac2dfd650`.
- Модели, CUDA, разрешение изображений, seed=42, параметры генерации,
  3 попытки с обратной связью, строгий JSONL-парсер, валидация и метрики
  совпадают с `../validation_2026-11-13/`. Меняется только текст промпта
  (и служебные имя Comet-эксперимента и каталог результатов).
- Qwen: Transformers BF16, без квантования, ревизия
  `89644892e4d85e24eaac8bacfd4f463576704203`.
- Gemma: llama.cpp, UD-Q4_K_XL, ревизия
  `980b060c40a8539ac159e0501a3e0f66a6365af3`.
- Каждый вариант запускается в отдельном процессе. Межпроцессная блокировка
  `/tmp/butterfly-prompt-search-gpu.lock` охватывает загрузку, обработку,
  завершение процесса и очистку его группы (включая llama-server).
  `gpu_schedule.jsonl` фиксирует получение и освобождение блокировки.
- Логирование Comet использует существующий режим `auto`; фактический URL
  каждого эксперимента записан в его `comet.json`. Полные промпты хранятся
  в YAML и артефактах, поскольку Comet ограничивает длину строк параметров.
- Победитель: максимальная F1@IoU=0.5; при равенстве — F1@0.75,
  затем меньше окончательных технических ошибок.

Это подбор на валидационной выборке, поэтому качество выбранного промпта
на этих 100 изображениях не является независимой тестовой оценкой.

## Адаптация ещё не испытанных вариантов

Первоначально каждый агент подготовил десять кандидатов. После первых результатов
укороченные инструкции формата оказались хуже исходных: Qwen стал добавлять
Markdown-обёртки, а Gemma — часто терять десятичную точку в координате `top`.
Это наблюдение, а причинная роль отдельных формулировок остаётся гипотезой.

Для оставшихся вариантов Qwen 04–10 и Gemma 04–07,09–10 сохранён исходный подробный
контракт JSONL и добавлены разные инструкции по локализации. Уже испытанные
тексты и результаты не изменяются. Gemma 03 и 08 сохранены как диагностические
сравнения с первоначальным сокращённым контрактом. Исходные планы и журнал
изменений сохранены рядом с финальными промптами. Это адаптивный подбор,
а не сравнение полностью заранее зафиксированных десяти запросов.

## Запуск и артефакты

Из корня репозитория можно запускать оба скрипта одновременно: GPU будет
использоваться последовательно. Существующие завершённые варианты пропускаются,
а незавершённый запуск требует проверки, чтобы его артефакты не перезаписывались.

```bash
.venv/bin/python scripts/prompt_search_qwen.py
.venv/bin/python scripts/prompt_search_gemma.py
```

В каждом каталоге модели: `prompts.json`, каталоги всех десяти прогонов,
`summary.json`, `best_prompt.json`, `best_prompt.txt` и `report.md`.
В каждом прогоне — полная конфигурация, исходные ответы всех попыток,
итоговые предсказания, метрики, тайминги, журнал GPU и ссылка Comet.

Первый старт Gemma не поместился в VRAM из-за постороннего ROS-процесса.
Артефакты сохранены в `gemma/startup_failures/`, эксперимент не получил
предсказаний и не считается одним из десяти оценённых промптов. ROS-процесс
остановлен по явному разрешению пользователя; проверено освобождение 1840 MiB.

## Результаты

Завершены **20 полных прогонов по 100 изображений**: десять разных промптов
на каждую модель, включая точное повторение исходного. Ни одна фотография
с окончательной ошибкой обработки не исключена из метрик.

| Модель / промпт | F1@0.5 | F1@0.75 | Precision@0.5 | Recall@0.5 | FP+FN | Технические отказы | Обработка, с |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| qwen / baseline | 0.078740 | 0.000000 | 0.075758 | 0.081967 | 117 | 8 | 481.7 |
| qwen / four_edges | 0.473684 | 0.070175 | 0.509434 | 0.442623 | 60 | 0 | 99.3 |
| gemma / baseline | 0.915254 | 0.542373 | 0.947368 | 0.885246 | 10 | 1 | 170.3 |
| gemma / 08_json_contract_first | 0.950000 | 0.600000 | 0.966102 | 0.934426 | 6 | 0 | 162.2 |

Время — сумма обработки изображений с повторными попытками; загрузка модели,
ожидание GPU и завершение отправки в Comet сюда не входят.

Все десять вариантов, полные тексты и причины отклонений:

- [Qwen: отчёт](qwen/report.md), [лучший промпт](qwen/best_prompt.txt).
- [Gemma: отчёт](gemma/report.md), [лучший промпт](gemma/best_prompt.txt).

У Qwen изменение включает инструкции локализации и формата, поэтому вклад
каждой формулировки отдельно не установлен. Даже лучший вариант нужно оценивать
по обоим IoU: допустимая структура ответа сама по себе не означает точную рамку.

Промпт Qwen `four_edges` просит найти четыре крайние точки насекомого и отдельно
оценить положение и размер рамки. У Gemma `08_json_contract_first` сначала описывает
JSON-контракт, затем даёт пример перевода крайних координат в размеры рамки.

Прирост Gemma по F1@0.5 составил +0.034746. Перенос улучшений обеих моделей
на другие данные пока не измерен. Независимый split `test` не использовался.

## Проверка результатов и применение

[audit.json](audit.json) фиксирует повторный пересчёт метрик всех 20 прогонов,
совпадение порядка 100 ID, неизменность остальных настроек, seed каждой попытки
и SHA256 конфигураций, ответов и метрик. Все GPU-сессии в журнале идут без
пересечений; стартовая OOM-сессия учтена отдельно от двадцати оценок.

При завершении подбора выбранные тексты были сохранены в пресетах `*_tuned`.
Затем эти рабочие пресеты адаптированы к `boxes_only`; точные исторические тексты
остаются в `best_prompt.txt` и `config.yaml` соответствующих прогонов. Старый
протокол воспроизводят скрипты подбора выше; для текущих пресетов команды ниже
запускают валидацию с новым форматом ответа:

```bash
.venv/bin/python -m butterfly_bench model=qwen_tuned \
  data.revision=1316e3c7147d4399a03f90684e191aae4d798f09
.venv/bin/python -m butterfly_bench model=gemma_tuned \
  data.revision=1316e3c7147d4399a03f90684e191aae4d798f09
```

Эти команды запускаются по очереди; общая блокировка используется именно
скриптами подбора. Для инференса без эталонов можно выбрать те же пресеты
с `mode=inference data=manifest data.path=...`.

Comet ограничивал доставку артефактов. Полнота облачной копии не подтверждена;
локальные результаты полные, а SDK сохранил offline ZIP для недоставленных данных
в `<variant>/comet-offline/` (первые — в `.cometml-runs/`). Архивы не входят в Git.

ROS-контейнер после разрешённой остановки не перезапускался.
