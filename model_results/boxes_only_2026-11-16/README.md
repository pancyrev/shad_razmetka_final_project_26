# Проверка ответа VLM без служебных полей

Архив эксперимента из коммита `60e988a`. По просьбе пользователя прежний
формат с photo_id в ответе восстановлен; новый прогон находится в
[restored_task_record_2026-11-16](../restored_task_record_2026-11-16/README.md).

Qwen и Gemma возвращают одну JSONL-строку `{"boxes": [...]}`. Парсер проверяет
структуру и координаты, затем добавляет `photo_id` из входного Sample и `error: null`.
При окончательном отказе пайплайн записывает `boxes: null` и диагностический `error`.
Итоговые predictions/submission JSONL сохраняют прежнюю схему из трёх полей.

Проверены `qwen_tuned` и `gemma_tuned` на тех же 100 validation-изображениях,
61 рамке и 42 отрицательных примерах. Ревизии весов/данных, seed=42, параметры
генерации, три попытки, препроцессинг и метрики сохранены. GPU использовался
последовательно под общей flock-блокировкой; Qwen полностью завершён перед Gemma.
Независимый split test не использовался.

Время — обработка изображений с повторами, без загрузки модели, ожидания GPU
и завершения Comet. Старые числа относятся к выбранным промптам из
[исторического подбора](../prompt_search_2026-11-15/README.md).

Это сравнение полных инструкций вывода: удалены ID, константа error=null и
соответствующие требования к JSON. Отдельный причинный эффект удаления только
ID не изолирован. У Gemma дополнительно испытано уточнение: полный числовой
пример JSON и явное требование долей для top после 23 отказов схемы
в первой адаптации. Первый прогон сохранён в gemma_initial. Это адаптивная
доработка на validation. Уменьшение ошибок формата не гарантирует роста всех метрик
детекции; например, у Qwen F1@0.5 выросла, а F1@0.75 и precision снизились.

В версии `60e988a` обычные `model=qwen` / `model=gemma` также использовали boxes_only. Их исходная
стратегия локализации сохранена; таблица выше относится именно к *_tuned.

## Воспроизведение

Команды и `validation_driver.py` ниже рассчитаны на исходный код версии `60e988a`.

```bash
.venv/bin/python -m butterfly_bench model=qwen_tuned \
  data.revision=1316e3c7147d4399a03f90684e191aae4d798f09
.venv/bin/python -m butterfly_bench model=gemma_tuned \
  data.revision=1316e3c7147d4399a03f90684e191aae4d798f09
```

Запускайте последовательно. `validation_driver.py` — точный сценарий этих
прогонов с чтением уже закешированного Parquet без Hub metadata-запросов.

## Проверки и артефакты

В каждом каталоге сохранены config, data, сырые ответы всех попыток,
предсказания, метрики, тайминги, GPU и model metadata. Submission сохраняется
только при успешной обработке всех изображений; здесь он есть у Qwen.
Comet работает в прежнем режиме auto/online; ссылки находятся в `<model>/comet.json`.
Локальные файлы полные; отдельная проверка полноты облачной копии не проводилась.

`audit.json` подтверждает отсутствие ID в каждом реальном запросе, строгую
проверку ответов, добавление метаданных из входа и пересчёт метрик по рамкам.
44 автоматических теста и линтер прошли. Исторические сырые ответы и метрики
не изменены; для их воспроизведения скрипты подбора явно включают task_record.
