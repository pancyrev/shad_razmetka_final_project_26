# Подбор промпта Gemma на validation

## Методика

В переборе десять уникальных промптов из `prompts.json`; исходный
промпт входит как `01_baseline`. Каждый вариант обработан
на всех тех же 100 фотографиях validation `xartik/inaturalist_butterflies`
(61 эталонная рамка, 42 отрицательных изображения), с seed 42.

Подбор адаптивный: после первых двух полных прогонов ещё не испытанные варианты
04–07 и 09–10 изменены так, чтобы сохранять полный текст baseline и добавлять
к нему конкретную инструкцию поиска/геометрии. Причина — вариант 02 с сокращённой
схемой дал 44 отказа валидатора и 13 окончательных ошибок против 5 и 1 у baseline.
Один из возможных факторов — отсутствие конкретного десятичного примера в
сокращённой схеме; причинный эффект пока не установлен. Варианты 01–03 и 08
не изменялись. Исходный план сохранён в `prompts_v1_initial.json`, момент и
основания пересмотра — в `prompt_revision_audit.json`. Уже выполненные прогоны
не заменялись; итоговое сравнение по-прежнему содержит ровно десять полных вариантов.

Изменяется только текст `model.prompt`. Используются исходные параметры из
`results/experiments/validation_2026-11-13/gemma/config.yaml`: Gemma 4 12B,
UD-Q4_K_XL, llama.cpp, полный CUDA offload, `image_max_tokens=560`,
`image_max_side=1280`, `context_size=8192`, `batch_size=ubatch_size=1024`.
Парсер JSONL, валидатор геометрии, три попытки с обратной связью и алгоритм
расчёта метрик остаются прежними. Весы и validation берутся из локального
кеша по исходным commit. Сырые ответы и Comet сохраняются для каждого запуска.

Основной критерий выбора — F1@IoU 0.5; при равенстве — F1@IoU 0.75, затем
меньшее количество окончательных технических ошибок (`processing_errors`).
Межпроцессная блокировка `/tmp/butterfly-prompt-search-gpu.lock` охватывает
весь запуск и завершение llama-server, поэтому Qwen и Gemma не занимают
GPU одновременно. Память, занятая другими задачами, находится вне этой блокировки.

Это подбор на validation: результаты лучшего варианта на этих же 100 фотографиях
нельзя считать независимой оценкой. Для неё нужен отдельный test split,
который в этом переборе не используется.

## Варианты

| Вариант | Изменение относительно общей задачи |
| --- | --- |
| `01_baseline` | Исходный промпт без изменений |
| `02_compact` | Краткая инструкция и точная схема |
| `03_edges_then_extents` | Четыре видимых экстремума перед вычислением ширины/высоты |
| `04_visual_scan` | Последовательный просмотр всей картинки, поиск нескольких объектов |

что и исторический прогон. Проверка `verification.json` также сверяет для всех
десяти вариантов фактический `config.model.prompt` с финальным списком, остальные
настройки с baseline, ID, seed каждой попытки, повторный строгий парсинг сырых

Время относится к обработке изображений с повторами, без загрузки модели, ожидания GPU lock и доставки в Comet.

## Лучший промпт

```text
Output exactly one line of valid JSON, without Markdown or explanation. Use exactly {"photo_id":THE_INTEGER_ID,"boxes":[{"left":X,"top":Y,"width":W,"height":H}],"error":null}. Each box has exactly the four named numeric fields. Use normalized fractions of image dimensions, never pixels or a 0-1000 scale. The top-left of the image is (0,0), bottom-right is (1,1). left=x_min/image_width; top=y_min/image_height; width=(x_max-x_min)/image_width; height=(y_max-y_min)/image_height. All numbers must be finite. left>=0, top>=0, width>0, height>0, left+width<=1 and top+height<=1. If no adult butterflies are present use "boxes": []. Copy the supplied photo_id as an integer and set error to null. For example, an object occupying x=20% through 70% and y=10% through 60% would have {"left":0.2,"top":0.1,"width":0.5,"height":0.5}. This is an example of arithmetic only, not a proposed box for this image. The output boxes must come from this image. Locate every adult butterfly. Exclude moths, caterpillars, pupae, other insects, flowers and shadows. Return one tight axis-aligned rectangle for each butterfly, including all its visible wings, body, antennae and legs. For occluded or cropped animals, box the visible part only. 
```

К каждому запросу пайплайн добавляет `The photo_id for this image is <ID>.`; при отказе — сообщение валидатора. Полный текст каждой попытки сохранён в соответствующем `attempts.jsonl`.

## Артефакты и ограничения

Каталоги вариантов содержат `config.yaml`, `attempts.jsonl`, `predictions.jsonl`, `metrics.json`, `data.json`, `model.json`, `gpu.jsonl`, `llama-server.log`, `run.log` и данные Comet. Сохранены [сводка](summary.json), [текст лучшего промпта](best_prompt.txt) и [его JSON-запись](best_prompt.json).

Comet использовал режим auto/online, но сервер ограничивал загрузку. SDK сохранял offline ZIP для недоставленных данных. Полнота облачной копии не подтверждена; локальные метрики и сырые ответы сохранены полностью. Fallback первого запуска может находиться в `.cometml-runs/` в корне репозитория, последующих — в `<variant>/comet-offline/`.

Первая попытка загрузки baseline завершилась CUDA OOM до обработки изображений из-за дополнительной ROS задачи на GPU. Её диагностика сохранена в `startup_failures/2026-11-16T102234Z_baseline_oom/` и не включается в таблицу. После разрешённой пользователем остановки ROS все варианты запускались с исходными параметрами.
